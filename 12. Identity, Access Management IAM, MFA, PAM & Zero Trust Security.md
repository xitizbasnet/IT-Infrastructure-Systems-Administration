# 12.1 Identity & Access Management (IAM)

---

## Step 1: Define RBAC Roles

🔐 Establish Role-Based Access Control (RBAC):

### Process:

* Map:

  * Business functions → Roles → Permissions
* Apply **Least Privilege Principle**

📍 Navigate:

```text id="iam_001"
Entra ID → Roles and Administrators
```

### Actions:

* Assign:

  * Built-in roles OR
  * Custom roles

📌 Purpose:

* Ensures users only access required resources
* Reduces security exposure

---

## Step 2: Access Reviews

🔍 Periodic access validation:

📍 Navigate:

```text id="iam_002"
Entra ID → Identity Governance → Access Reviews → New
```

### Configuration:

* Schedule: **Quarterly reviews**
* Scope: Privileged roles

📌 Purpose:

* Removes unnecessary or stale access permissions
* Enforces compliance and audit readiness

---

# 12.2 Privileged Access Management (PAM)

---

## Step 1: Enable Entra PIM

🛡️ Configure Privileged Identity Management:

📍 Navigate:

```text id="pam_001"
Entra ID → Privileged Identity Management → Manage roles
```

---

### Configuration:

* Set **Global Administrator** role to:

  * Eligible (not permanent)
* Require:

  * Justification
  * MFA for activation

📌 Purpose:

* Prevents always-on administrative access
* Reduces attack surface for privileged accounts

---

## Step 2: Just-In-Time (JIT) Access

⏱️ Temporary elevation of privileges:

📍 Navigate:

```text id="pam_002"
PIM → My Roles → Activate
```

### Configuration:

* Duration: Up to **8 hours**
* Requires approval workflow

📌 Purpose:

* Grants time-limited administrative access
* Improves security governance

---

# 12.3 Multi-Factor Authentication (MFA)

---

## Step 1: Enforce MFA via Conditional Access

🔐 Enforce identity verification:

📍 Navigate:

```text id="mfa_001"
Entra ID → Conditional Access → New Policy
```

### Configuration:

* Users: All users
* Control: Require MFA
* Exclusions:

  * Break-glass accounts (emergency admin accounts)

📌 Purpose:

* Prevents unauthorized account access even if passwords are compromised

---

## Step 2: Authentication Methods Configuration

🔑 Define allowed authentication methods:

📍 Navigate:

```text id="mfa_002"
Entra ID → Security → Authentication Methods → Policy
```

### Enable:

* Microsoft Authenticator (Push Notifications)
* FIDO2 Security Keys (Passwordless)

### Disable:

* SMS Authentication (high SIM-swap risk for privileged accounts)

📌 Purpose:

* Strengthens authentication security posture

# BEST PRACTICE TIPS

---

## 🚨 Break-Glass Accounts

* Must:

  * Bypass Conditional Access
  * Be monitored 24/7

📌 Purpose:

* Ensures emergency access during identity outages

---

## 📊 Sign-In Risk Policies

* Use Entra ID Protection to:

  * Detect risky sign-ins
  * Block suspicious authentication attempts automatically

📌 Purpose:

* Prevents compromised account access in real time

---

## 📅 PIM Audit Reviews

* Review privileged assignments monthly

📌 Purpose:

* Ensures no persistent unauthorized admin access

---

## 🔐 Password Protection Policy

* Enable:

  * Entra ID Password Protection
  * Ban weak and common passwords (on-prem + cloud)

📌 Purpose:

* Prevents credential stuffing attacks

---

## 🧠 Zero Trust Model

### Core Principles:

* Verify explicitly
* Use least privilege access
* Assume breach

📌 Purpose:

* Modern security architecture standard for enterprise environments
