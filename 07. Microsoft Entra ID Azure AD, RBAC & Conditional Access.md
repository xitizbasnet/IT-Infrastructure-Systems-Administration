# Objective

Configure Azure subscriptions, Resource Groups, identity management, and Conditional Access.

---

# 7.1 Azure Subscription & Resource Groups

---

## Step 1: Create Resource Group

📦 Create a logical container for Azure resources:

```bash id="az_rg_001"
az group create --name RG-Production --location australiaeast
```

📌 Purpose:

* Organizes Azure resources logically
* Enables lifecycle and cost management

---

## Step 2: Assign RBAC Role

🔐 Assign role-based access control (RBAC):

```bash id="az_rbac_001"
az role assignment create --assignee user@corp.com --role 'Contributor' --scope /subscriptions/<subscription-id>/resourceGroups/RG-Production
```

📌 Purpose:

* Grants controlled access to Azure resources
* Ensures least privilege access model

---

# 7.2 Microsoft Entra ID (Azure AD)

---

## Step 1: Create Entra ID User

👤 Create a new identity in Microsoft Entra ID:

📍 Navigate:

```text id="entra_user_001"
Azure Portal → Entra ID → Users → New User
```

### PowerShell Alternative:

```powershell id="entra_user_002"
New-AzureADUser -DisplayName 'Jane Smith' -UserPrincipalName jane@corp.com -PasswordProfile $pass -AccountEnabled $true
```

📌 Purpose:

* Creates cloud identity for authentication and access control

---

## Step 2: Create Dynamic Group

👥 Automate group membership using rules:

📍 Navigate:

```text id="entra_group_001"
Entra ID → Groups → New Group
```

### Configuration:

* Membership Type: **Dynamic**
* Rule:

```text id="entra_group_rule_001"
(user.department -eq 'IT')
```

📌 Purpose:

* Automatically assigns users based on attributes
* Reduces manual group administration

---

## Step 3: Conditional Access Policy

🛡️ Enforce identity-based security controls:

📍 Navigate:

```text id="ca_policy_001"
Entra ID → Security → Conditional Access → New Policy
```

---

### Policy Configuration:

| Setting       | Value          |
| ------------- | -------------- |
| Users         | All users      |
| Cloud Apps    | All cloud apps |
| Grant Control | Require MFA    |

---

### Deployment Mode:

* Start in:

  * **Report-only mode**
* After validation:

  * Switch to **Enabled (On)**

📌 Purpose:

* Enforces Multi-Factor Authentication (MFA)
* Reduces risk of unauthorized access

---

# 7.3 Azure Virtual Machines

---

## Step 1: Create VM via Azure Portal

🖥️ Deploy virtual machine:

📍 Navigate:

```text id="vm_create_001"
Azure Portal → Create Resource → Virtual Machine
```

---

### Configuration:

| Setting        | Value                           |
| -------------- | ------------------------------- |
| Region         | Selected Azure region           |
| Size           | B2s (Development)               |
| Authentication | SSH Key / Password              |
| Networking     | New VNet + Subnet               |
| Inbound Ports  | SSH (22) restricted to admin IP |

📌 Purpose:

* Secure VM provisioning with restricted network access

---

## Step 2: Connect to Virtual Machine

🌐 Remote access methods:

### Linux VM (SSH)

```bash id="vm_ssh_001"
ssh adminuser@<public-ip>
```

---

### Windows VM (RDP)

```text id="vm_rdp_001"
mstsc /v:<public-ip>
```

📌 Purpose:

* Secure administrative access to cloud workloads

---

# BEST PRACTICE TIPS

---

## 🏷️ Azure Policy Enforcement

* Use Azure Policy to enforce:

  * Resource tagging
  * Allowed regions
  * Compliance rules

📌 Purpose:

* Ensures governance at scale
* Prevents resource sprawl

---

## 🛡️ Microsoft Defender for Cloud

* Enable for all subscriptions

📌 Purpose:

* Provides:

  * Threat detection
  * Security recommendations
  * Compliance monitoring

---

## 🔐 Managed Identities

* Use Managed Identities instead of storing credentials

📌 Purpose:

* Eliminates hardcoded secrets
* Improves security posture

---

## 🔑 Least Privilege Access

* Assign only required permissions via RBAC

📌 Purpose:

* Minimizes attack surface
* Limits accidental misconfiguration

---

## ⏱️ Privileged Identity Management (PIM)

* Enable Just-In-Time (JIT) admin access

📌 Purpose:

* Temporary elevation of privileges
* Reduces persistent admin risk

---

## 🔒 Resource Locking

* Apply locks to critical resource groups:

| Lock Type    | Purpose                     |
| ------------ | --------------------------- |
| CanNotDelete | Prevent accidental deletion |

📌 Purpose:

* Protects production environments from accidental changes
