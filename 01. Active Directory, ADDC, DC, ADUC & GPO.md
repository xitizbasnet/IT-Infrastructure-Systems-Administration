# Active Directory, ADDC, DC, ADUC & GPO

> 📘 **Document Type:** Windows Server Active Directory Deployment Lab Guide
> 
> 🏢 **Department:** Information Technology (IT)
> 
> 🎯 **Objective:** Deploy and configure a Windows Server Domain environment including Active Directory Domain Services (AD DS), Domain Controllers, Active Directory Users & Computers (ADUC), and Group Policy Objects (GPO).

---

# Objective

Deploy and configure a Windows Server Domain environment.

---

# 1.1 Install Active Directory Domain Services (AD DS)

---

## Step 1: Prepare the Server

🖥️ Configure base server settings:

* Assign Static IP:

  * Example: `192.168.1.10`
* Set DNS to:

  * `127.0.0.1`

### Rename Server

Navigate:

📍 `Server Manager > Local Server > Computer Name`

Rename the server to a meaningful hostname.

---

## Step 2: Install AD DS Role

📦 Open Server Manager:

📍 `Add Roles & Features`

### Select:

* Active Directory Domain Services (AD DS)
* Include management tools

▶️ Complete wizard and click **Install**

---

## Step 3: Promote Server to Domain Controller

📢 After installation:

Click notification flag → **Promote this server to a domain controller**

---

### Configuration Options

* Select: **Add a new forest**
* Root domain name:

  * Example: `corp.local`

---

### Additional Settings

* Set DSRM password
* Keep default DNS settings
* Keep NetBIOS settings
* Confirm file paths

▶️ Click **Install**

🔄 Server will reboot automatically after promotion.

---

# 1.2 Add an Additional Domain Controller (ADDC)

---

## Step 1: Join Secondary Server to Domain

🖧 Configure DNS:

* Set secondary server DNS to Primary DC IP

---

### Join Domain

Navigate:

📍 `System Properties > Change`

* Select Domain:

  * `corp.local`

---

## Step 2: Install AD DS & Promote

📦 Repeat AD DS role installation on secondary server.

---

### Promotion Steps

* Select: **Add a domain controller to an existing domain**
* Enable:

  * DNS Server
  * Global Catalog
* Enter administrative credentials
* Complete installation

---

# 1.3 ADUC — Active Directory Users & Computers

---

## Step 1: Create Organizational Units (OUs)

📂 Open ADUC:

```text id="aduc001"
dsa.msc
```

### Create OUs:

* IT_Dept
* HR_Dept
* Finance_Dept

---

## Step 2: Create User Accounts

👤 User creation process:

* Right-click OU → New → User
* Enter:

  * First Name
  * Last Name
  * Logon Name

### Password Policy Options

* Set password
* Optional:

  * Uncheck **“User must change password at next logon”** for service accounts

---

## Step 3: Create Security Groups & Add Members

👥 Group creation:

* Right-click OU → New → Group

### Group Settings:

* Group Scope: Global
* Group Type: Security

---

### Add Members

* Open group
* Navigate to **Members tab**
* Add users as required

---

# 1.4 Group Policy Objects (GPO)

---

## Step 1: Open Group Policy Management Console

📍 Run:

```text id="gpo001"
gpmc.msc
```

---

## Step 2: Create a New GPO

📌 Navigate:

* Right-click target OU
* Select:

  * **Create a GPO in this domain and link it here**

---

### GPO Naming Convention

Example:

* `Password_Policy`

---

## Step 3: Edit GPO — Password Policy

📍 Navigate:

```
Computer Configuration
→ Windows Settings
→ Security Settings
→ Account Policies
```

### Configure Settings:

* Minimum Password Length: **12**
* Password Complexity: **Enabled**
* Maximum Password Age: **90 days**

---

## Step 4: Edit GPO — Desktop Restrictions

📍 Navigate:

### User Configuration → Administrative Templates

#### Control Panel

* Prohibit access: **Enabled**

#### System

* Prevent access to registry tools: **Enabled**

---

## Step 5: Force Policy Update

🔄 Apply policy immediately:

```bash id="gpupdate001"
gpupdate /force
```

---

# BEST PRACTICE TIPS

---

## 🧪 Test Before Production

* Always test GPOs in a **pilot OU**
* Avoid applying directly to production OUs

---

## ⚠️ Use of Enforced GPOs

* Use **“Enforced”** sparingly
* Only apply when lower-level OUs must NOT override settings

---

## ♻️ Active Directory Recovery

* Enable **AD Recycle Bin**

  * Command: `Enable-ADOptionalFeature`

📌 Purpose:

* Recover deleted AD objects

---

## 🖥️ Domain Controller Redundancy

* Maintain at least **two Domain Controllers per domain**
* Ensures:

  * High availability
  * Fault tolerance

---

## 🔍 AD Security Auditing

* Enable AD DS auditing via:

  * Default Domain Controllers Policy
  * Audit Policy settings

📌 Purpose:

* Track login activity
* Monitor changes in directory structure

---

## 📄 Documentation Standards

* Document every GPO with:

  * Clear name
  * Purpose description
  * Scope (which OU it applies to)

📌 Store documentation in:

* Group Policy Management Console notes
* Central IT documentation repository
