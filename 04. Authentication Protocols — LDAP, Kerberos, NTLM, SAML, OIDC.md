# 4.1 LDAP — Lightweight Directory Access Protocol

---

## Step 1: Test LDAP Connectivity

🔎 Validate LDAP communication with domain controller:

```bash id="ldap001"
ldapsearch -x -H ldap://dc01.corp.local -b 'DC=corp,DC=local' -D 'CN=svc_ldap,OU=ServiceAccts,DC=corp,DC=local' -W '(objectClass=user)'
```

📌 Purpose:

* Verifies LDAP query access to Active Directory
* Confirms service account authentication

---

## Step 2: Secure LDAP (LDAPS) — Enable on AD

🔐 Enable encrypted LDAP communication:

### Requirements:

* SSL certificate installed on Domain Controller

  * Internal CA OR
  * Self-signed certificate

---

### Verification Using LDP Tool

```text id="ldaps001"
ldp.exe → Connection → Connect → Port 636 → SSL Enabled
```

📌 Purpose:

* Confirms LDAPS (secure LDAP over SSL/TLS) is active

# 4.2 Kerberos Authentication Flow

---

## Step 1: Verify Kerberos Tickets (Windows)

🎟️ Check active Kerberos tickets:

```bash id="kerb001"
klist
```

📌 Purpose:

* Displays cached authentication tickets
* Confirms Kerberos authentication is working

---

## Step 2: Kerberos Troubleshooting

### Common Errors

| Error Code               | Meaning                    |
| ------------------------ | -------------------------- |
| `KDC_ERR_PREAUTH_FAILED` | Incorrect password         |
| `KRB_AP_ERR_SKEW`        | Time synchronization issue |

---

### Time Synchronization Fix

⏱️ Ensure clock alignment using NTP:

* Time skew must be < 5 minutes

---

### FSMO Role Verification

```bash id="kerb002"
netdom query fsmo
```

📌 Purpose:

* Confirms Key Distribution Center (KDC) role ownership

# 4.5 OIDC — OpenID Connect

---

## Step 1: Register Application in Entra ID

🌐 Navigate:

```text id="oidc001"
Entra ID → App Registrations → New Registration
```

---

### Configuration:

* Set Redirect URI
* Record:

  * Application (Client) ID
  * Directory (Tenant) ID

---

### Create Client Secret:

* Certificates & Secrets → New Client Secret

📌 Purpose:

* Enables secure token-based authentication

---

## Step 2: OIDC Token Request (PowerShell)

🔑 Request OAuth2 token:

```powershell id="oidc002"
$body = @{
 grant_type    = 'client_credentials'
 client_id     = ''
 client_secret = ''
 scope         = 'https://graph.microsoft.com/.default'
}

Invoke-RestMethod -Method POST `
-Uri 'https://login.microsoftonline.com//oauth2/v2.0/token' `
-Body $body
```

📌 Purpose:

* Retrieves access token for API authentication
* Used for Microsoft Graph and enterprise integrations

# BEST PRACTICE TIPS

---

## 🔐 Prefer Kerberos Over NTLM

* Kerberos is:

  * More secure
  * Mutual authentication capable
* Disable NTLMv1 using Group Policy

---

## 🔒 Use LDAPS Only

* Always prefer:

  * LDAPS (Port 636)

🚫 Disable:

* Plain LDAP (Port 389)

📌 Purpose:

* Prevent credential interception

---

## 🔁 Certificate Management

* Rotate SAML signing certificates annually
* Update Service Provider metadata after rotation

---

## ⏱️ Token Security

* Implement strict token lifetime policies
* Reduce session hijacking risk

---

## 🛡️ Conditional Access

* Enable Conditional Access policies before deploying SSO

📌 Purpose:

* Enforces:

  * MFA
  * Device compliance
  * Location-based access rules
