# 15.1 Backup Strategy Overview

---

## Step 1: 3-2-1 Backup Rule

🛡️ Standard enterprise backup strategy:

* **3** copies of data
* **2** different storage media types
* **1** offsite or cloud copy

📌 Requirement:

* Apply this rule across all backup solutions listed below

📌 Purpose:

* Ensures redundancy, resilience, and disaster recovery readiness

---

# 15.2 NAS Backup (Synology / QNAP Example)

---

## Step 1: Install Backup Agent on Windows

📦 Install NAS backup client:

### Synology

* Install: **Synology Active Backup for Business Agent**

### QNAP

* Install: **NetBak Replicator** OR
* Install: **Hyper Data Protector Agent**

📌 Purpose:

* Enables endpoint-to-NAS backup integration

---

## Step 2: Create Backup Task

🖥️ Configure backup job:

📍 Navigate:

```text id="nas_backup_001"
NAS Management UI → Active Backup → Create Task → PC Backup
```

---

### Configuration:

* Add device
* Select volumes:

  * C: Drive
  * D: Drive
* Schedule:

  * Daily at 11:00 PM

---

### Retention Policy:

| Type            | Retention   |
| --------------- | ----------- |
| Daily Backups   | 30 versions |
| Monthly Backups | 12 versions |

📌 Purpose:

* Ensures long-term versioning and recovery capability

---

# 15.3 Veeam Backup & Replication

---

## Step 1: Add Windows Machine

🧩 Add endpoint to Veeam:

📍 Navigate:

```text id="veeam_001"
Veeam Console → Infrastructure → Add → Microsoft Windows
```

---

### Configuration:

* Enter hostname/IP
* Provide credentials
* Agent installed automatically

📌 Purpose:

* Enables centralized backup management

---

## Step 2: Create Backup Job (Agent-Based)

💾 Configure backup job:

📍 Navigate:

```text id="veeam_002"
Home → Backup Job → Windows Computer → Workstation/Server
```

---

### Backup Mode Options:

* Entire Computer
* Selected Volumes:

  * C:
  * D:

---

### Destination:

* Veeam Backup Repository

  * NAS OR Cloud storage

---

### Schedule:

| Type         | Schedule     |
| ------------ | ------------ |
| Daily Backup | 10:00 PM     |
| Full Backup  | Every Sunday |

📌 Purpose:

* Ensures consistent recovery points and structured backups

---

## Step 3: Verify Backup with SureBackup

🧪 Validation:

📍 Navigate:

```text id="veeam_003"
Veeam → Home → SureBackup Job
```

* Run recovery verification test

📌 Purpose:

* Confirms backup integrity and recoverability

---

☁️ Install endpoint agent:

📍 Navigate:

```text id="barracuda_001"
Barracuda Backup Portal → Add Source → Windows Agent
```

---

### Steps:

* Download agent
* Install on endpoint
* Approve via portal token

📌 Purpose:

## Step 2: Configure Data Sources

📂 Define backup scope:

📍 Navigate:

```text id="barracuda_002"
Portal → Sources → Add
```

---

### Selection:

* C: Drive
* D: Drive

### Feature:

* Enable **LiveBoot**

📌 Purpose:

* Enables instant system recovery capability

## Step 3: Cloud Replication

☁️ Enable offsite backup:

📍 Navigate:

```text id="barracuda_003"
Portal → Replication → Enable
```

* Provides offsite disaster recovery protection

# 15.5 Backblaze Business Backup

---

## Step 1: Install & Activate

☁️ Install backup client:

* Download from: Backblaze Business Backup portal
* Install on Windows endpoint
* Sign in with business account

📌 Behavior:

* Automatically backs up all drives except excluded system temp files

---

## Step 2: Configure External / D: Drive

⚙️ Ensure correct inclusion:

📍 Navigate:

```text id="backblaze_001"
Settings → Exclusions
```

* Ensure D: is NOT excluded

---

### Performance Settings:

| Setting        | Action                 |
| -------------- | ---------------------- |
| Backup Threads | Adjust for performance |
| Throttling     | Enable as needed       |

📌 Purpose:

* Optimizes backup speed and system performance

---

## Step 3: Restore Files

🔄 File recovery process:

📍 Navigate:

```text id="backblaze_002"
Web Portal → Sign In → View / Restore Files
```

### Restore Options:

* Select date/version
* Download ZIP file OR request physical drive restore

📌 Purpose:

* Enables flexible recovery options

# 15.6 Druva inSync / Phoenix

---

## Step 1: Deploy inSync Agent (Endpoint Backup)

☁️ Cloud deployment:

📍 Navigate:

```text id="druva_001"
Druva Cloud Console → Deploy → Endpoints → Download Agent
```

* Install agent on endpoints
* Auto-registers with cloud platform

📌 Purpose:

* Enables centralized SaaS-based backup management

---

## Step 2: Configure Backup Sets

📊 Define backup policy:

📍 Navigate:

```text id="druva_002"
Cloud Console → Policies → Backup Policy
```

### Included Paths:

* C:\Users
* D:\
* Custom directories

---

### Features:

* Deduplication
* Encryption

---

### Schedule:

* Continuous backup OR
* Every 4 hours (business hours)

📌 Purpose:

* Ensures near real-time data protection

---

## Step 3: Druva Phoenix (Server Backup)

🖥️ Server protection:

* Install Phoenix agent on Windows Server

📍 Configure:

* Backup Rule → Select volumes
* Destination → Druva Cloud

---

### Security Feature:

* Enable **Air-Gap Protection**

📌 Purpose:

* Protects backups from ransomware deletion or modification

# 15.7 Verify & Test Restores

---

## Step 1: Monthly Restore Test

🧪 Validation procedure:

* Restore random file from each backup system
* Restore to test location
* Verify integrity:

  * Open file
  * Compare hash (if applicable)

📌 Purpose:

* Confirms backups are usable and not corrupted

---

## Step 2: Backup Reporting

📊 Monitor backup health:

* Review weekly reports from all platforms

---

### Alert Conditions:

| Condition         | Action                  |
| ----------------- | ----------------------- |
| Job failure       | Investigate immediately |
| >10% failure rate | Escalate                |
| Storage >80%      | Expand capacity         |

📌 Purpose:

* Ensures proactive backup management

# BEST PRACTICE TIPS

---

## 🛡️ Follow the 3-2-1 Rule

* 3 copies of data
* 2 different media types
* 1 offsite backup

---

## 🔄 Test Restores Regularly

* Monthly restore testing required

📌 Purpose:

* A backup is only valid if restoration works

---

## 🔐 Enable Immutable & Air-Gapped Backups

* Protect against ransomware deletion

---

## 🔒 Encrypt Backup Data

* At rest AND in transit
* Store encryption keys separately

---

## 📄 Define RPO & RTO

* RPO: Maximum acceptable data loss
* RTO: Maximum acceptable downtime

---

## 🚫 Optimize Backup Scope

Exclude:

* Temp files
* Cache directories
* Pagefile.sys

---

## 🔑 Secure Backup Credentials

* Store in:

  * PAM (Privileged Access Management) vault
* Never store in plaintext
